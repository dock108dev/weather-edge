# Weather Edge audit remediation plan

The November 16 audit found two ways historical results could mislead. Replay used a model whose availability was first witnessed after the selected clock, and the simulator filled cases that Trade blocked on listing windows or fee terms. Milestone 1 resolved the replay and startup findings. Slices 3 and 4 address the remaining listing and fee mismatch before interpreting differences in strategy performance.

This plan covers the full audit and the enhancements needed to make the repaired paths easier to operate. Slices are ordered by dependency and evidence. Split a slice whenever its changes can be integrated and verified independently. The audit baseline was staged tree `228d4f6efd6960e7b3498d768109e3ccefe0ee81` on an unborn `main`. The baseline build matched the running app and 166 Python tests passed. The audit also reproduced defects in that build and found tests that passed when every quote row disappeared.

## Working rules

- Weather Edge remains local and paper-only. Preserve exact source receipts, native IDs, archived studies, saved strategy runs, the live and fixture ledgers, and the collector's explicit Stop state. Keep normal use on port 8765. Use a disposable data root and a separate port for tests that write state or interrupt processes.
- Treat listing quotes, book offers, modeled probabilities, executable paper previews, rechecks, and verified payouts as separate facts. Show a price when the retained evidence supports displaying it. Require the existing depth, origin, age, fee, model, edge, and delayed recheck evidence for paper actions.
- Preserve the observation or forecast issue clock, forecast valid time, source or exchange clock, and local availability clock at their original precision. Keep the market's local contract date separate from UTC evaluation ranges. A later revision, receipt, payout, or artifact cannot supply evidence for an earlier decision.
- Use the same retained case and settings for before-and-after comparisons. Label fixture results, replayed decisions, and current browser observations. A repeated appearance of one side is an observation, and one station-day can contain multiple correlated sides.
- Preserve the existing index while taking a baseline. Stage changes by path when a slice is ready. Capture the evidence that resolved each finding and any remaining upstream dependency. A passing local check establishes local behavior. Hosted CI and deployment apply only when those environments exist and are in scope.
