## Operation

`book-recheck-v3` freezes exact instruments and native side IDs, selected listing receipt revisions, the fee schedule and signal lock time, receipt and app clocks, consulted probabilities, model availability evidence, settings, and rejection reasons. `witnessed-paper-v1` intents freeze reviewed quantity, price, cost, fee schedule, listing proof, the signal and recheck window, and the model identity. Captures use the first completed local capture for the exact book as the app clock. Native batched receipts record that clock after archive publication. Older native receipts without a completion witness still support display. Fixture mode uses legacy freshness with the HTTP receipt clock. Receipt-led research can select that clock explicitly.

```sh
.venv/bin/python -m weather_edge.paper_runs save
.venv/bin/python -m weather_edge.paper_runs save --fixture
.venv/bin/python -m weather_edge.paper_runs save --freshness legacy --clock-basis http-receipt
.venv/bin/python -m weather_edge.paper_runs rerun 40ee74c6230a6dd3846fcbb7
.venv/bin/python -m weather_edge.paper_runs --data /path/to/disposable-data evaluate 40ee74c6230a6dd3846fcbb7
.venv/bin/python -m weather_edge.paper_runs --data /path/to/disposable-data follow-payouts 40ee74c6230a6dd3846fcbb7
```

Live CLI save defaults to origin-confirmed freshness and app availability. Explicit `--freshness origin-confirmed` is also accepted in fixture mode and requires positive origin evidence there. `rerun` uses the frozen engine and verifies the original ID. `evaluate` saves a linked v3 result with changed decisions and missing evidence. A saved v2 Backtest exposes the same operation under **Evaluate frozen evidence under current rules**. Weather saves and reopens trials through `/api/runs`, with explicit old-evidence evaluation at `POST /api/runs/{id}/evaluate`. The CLI searches the normal trial, Backtest, and paper-order folders within its data root.
